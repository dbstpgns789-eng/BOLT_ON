# 볼트온이엔씨 법인 홈페이지 — 마스터 플랜

## Context

친구가 아버지에게서 양도받은 전기공사 업체 **볼트온이엔씨**(대표 장준혁)의 법인 홈페이지를 공식적으로 제작한다. 보수는 결과물의 품질에 따라 정해지고, 진행 중에 생기는 비용은 내가 먼저 결제한 뒤 최종 정산 때 청구한다.

1차 자료(요청서 답변 docx, 사례 사진 압축 파일 2개, 로고 JPG)는 이미 받았다. 클라이언트는 레퍼런스로 **우일이엔씨(http://www.wooilenc.com)** 를 지목하고 전체 분석을 요청했다. 이 계획의 목표는 세 가지다.

1. 클라이언트에게 무엇을 다시 요청할지 우선순위를 정해서, 사소한 요청 없이 **한 번에** 받는다.
2. 내가 정할 수 있는 것은 내가 정하고(ADR로 기록), 클라이언트만 답할 수 있는 것만 묻는다.
3. 요청서에서 약속한 진행 순서(자료 전달 → 첫 화면 확인 → 전체 제작 → 수정 최대 3회 → 오픈)에서 벗어나지 않는다.

## 0. 상황 변경 (2026-11-10 오후)

- 법인은 **법무사와 설립 진행 중**이다. 사업자등록증·전기공사업 등록증·영문 상호는 법인 설립 후에 확정된다.
- 방침: 임시 버전 없이 **최종 법인 홈페이지를 완성해 두고**, 법인·면허 정보를 받으면 **설정 파일 하나만 채워서 바로 오픈**한다.
- 회사 정보(상호, 영문 상호, 대표, 사업자번호, 면허번호, 설립일, 주소, 연락처, 도메인)는 `src/config/company.ts` 한 곳에서 관리하고, 비어 있는 항목은 화면에서 숨긴다.
- 영문 상호는 디스코드로 요청해 두었다(등기 영문명과 일치시킴). 도메인은 영문 상호와 법인이 확정된 뒤 법인 명의로 산다(ADR 0005 유지).

- **디자인 축 (2026-11-10 밤, 클라이언트 발언)**: "주축은 우일이엔씨". → 시안 C(브랜드형, 우일 흐름)를 기본안으로 하고, A(도면형)·B(현장형)는 클라이언트가 업계 9개 사이트에서 좋다고 고른 요소를 옮겨 올 부품 창고로 둔다. 클라이언트의 사이트별 좋은 점·싫은 점 회신을 기다린다.

- **Phase 4 완료 (2026-11-10 밤)**: 시안 A·B·C 폐기 → D 기반 D1~D4 → 클라이언트가 **D4** 선택. 푸터는 F3(하은형) 배치 + F1(우일형) 색. 홈(`/`)으로 확정했고 시안 목록은 `/drafts/`. 디자인 기준은 `docs/design-brief.md`. 다음은 Phase 5(하위 페이지).
- **홈에 남은 일(오픈 전)**: 링크 연결(하위 페이지 생성 후), 슬라이드 실제 현장 사진(서대문 원본 등), 회사 정보(법인명·사업자번호·면허번호·카카오 채널), 클라이언트 문구 사실 확인(사업분야 설명·진행 순서·한전 안내), SEO 메타·OG 이미지·구조화 데이터, 오픈 시 noindex 해제.
- **상담 예약 폼(사업분야 페이지, 2026-11-11 결정 A안)**: 오픈 전에 Web3Forms 키를 대표 이메일로 발급(무료)해 company.ts에 넣고, 개인정보처리방침 페이지를 만들고(요청서 5-4 초안 요청), 보관 기간(지금 임시로 "상담이 끝난 뒤 1년")을 클라이언트에게 확인한다.

- **Phase 5 진행 (2026-11-11 새벽)**: 사업분야 5개 페이지 완성(`/services/substation|capacity|transformer|wiring|newbuild/`). 틀은 시안 S4(소개+사진, 세부 업무, 담당 표시 진행 순서, 이 분야 사례, 상담 예약 폼, 다른 분야). 자주 묻는 질문은 클라이언트 결정으로 뺌. 홈 카드·메뉴·탭 링크 연결 완료. 남은 하위 페이지: 시공사례, 한전 신청 안내, 회사소개, 개인정보처리방침.
- **사업분야 문구 사실 확인 목록(클라이언트)**: 각 분야의 설명·필요한 경우·작업 범위·세부 업무·진행 순서(`src/data/service-pages.ts`). 특히 코드에 CHECK로 표시한 것: 시설부담금을 고객이 내는지(공사 이력에 '자사 납부'도 있음), 변압기 교체 후 사용전검사 여부. 신·증축과 변압기 교체에는 시공사례가 없음(김해 미술관은 내선·인테리어로 분류).

- **시공사례 확정 (2026-11-11)**: 목록 C2 카드 + 상세(대표 사진, 요약, 공사 전 상황, 정보 표, 번호 작업, 현장 사진 묶음). 비교 막대는 쓰지 않음(공사 전·후 사진이 꾸준히 생기면 나란히 비교 배치 재검토). 빈 값은 화면에 나오지 않는다.
  - 클라이언트에게 받을 것: 사례별 **공사 전 상황 한두 줄**, **용량(kW·kVA)**, 요약 문장 사실 확인. Phase 8 운영 안내의 새 사례 양식에 "공사 전 상황 한 줄" 칸을 넣는다.
  - **공사 이력 표는 폐기**(시공사례와 역할이 겹침). 회사소개를 만들 때 연혁 타임라인에 주요 공사를 넣는 방안으로 재검토.

- **회사소개 (2026-11-11)**: `/company/`(회사개요: 소개 문장, 일하는 방식 3가지, 회사 정보 표, 면허(등록 후 표시), 사업분야) + `/company/location/`(지도, 연락처, 네이버·카카오 길찾기, 방문 안내). 대표 인사말은 요청서 3-4에 따라 넣지 않음. 확인 필요: 도로명 주소(사업자등록증), "방문 전 전화" 안내 문구, 일하는 방식 문구(대표 문장을 나눔).
- **클라이언트 확인 방식**: 전체 페이지를 만든 뒤 한 번에 요청한다(2026-11-11).

## 1. 현재 자료 진단 (2026-11-10 기준)

### 받은 것
| 항목 | 상태 |
|---|---|
| 회사 소개문(3문장), 사업분야 5개 + 설명 | 있음. 다만 아래 "발견 사항" 1번 참고 |
| 진행 절차 | 상담 → 현장방문 → 견적 → 작업 → 완료 |
| 디자인 취향 | 남색 + 검정·회색 / 깔끔·믿음직 / 화려함·사진 과다는 피함 |
| 메뉴 | 회사 소개, 사업 분야, 작업 사례 |
| 문의 방식 | 전화 버튼 + 카카오톡 상담 (폼 없음) |
| 사례 5곳 | 김해 김영원 미술관, 서대문형무소, 제이알 배터리(군포), (주)조양(충북), 하나임푸드 변전실(청주) |
| 사례 사진 | **김해 미술관(이미지 9장 + 영상 1개), 하나임푸드(6장)만** 받음 |
| 로고 | JPG 1408×768 1장 (벡터 원본 없음) |
| 기타 | 도메인 없음, 기존 사이트 없음, 네이버 지도 미등록, 오픈일 미정, 포트폴리오 사용 가능 |

### 발견 사항 (계획에 영향을 주는 것)
1. **문구 중복**: 요청서의 '고압 수변전설비' 설명 중 "이 때 한전으로부터 공급받는 고압의 전기를 저압의 전기로 변전하여 세부시설로 공급합니다."가 우일이엔씨 사이트의 문장과 같다. 저작권과 검색 중복 문제 때문에 사업분야 문구는 **전부 새로 작성**하고, 클라이언트에게는 사실관계만 확인받는다.
2. **영문 상호 불일치**: 요청서에는 "Volt on E&C", 로고에는 "BOLT-ON E&C"로 적혀 있다. 도메인 이름과 로고가 여기에 달려 있으므로 최우선으로 확인한다.
3. **면허 '없음' 답변**: 전기공사는 전기공사업 등록 없이 할 수 없으므로 착오일 가능성이 높다. 등록증은 사이트 신뢰도에 가장 크게 기여하는 자료이다.
4. **거래처 공개 충돌**: 3-9에서는 "거래처 소개하지 않음"을 골랐지만, 3-7 사례에는 실제 회사 이름이 들어 있다.
5. **문의 폼 모호**: 5-1에서 폼을 고르지 않았는데, 5-3(받을 항목)과 5-4(개인정보처리방침 초안 요청)에는 표시가 되어 있다.
6. **사진 위치정보**: 김해 사진 4장(Galaxy Z Fold6 원본)에 GPS 정보가 들어 있다. 공개 전에 반드시 제거한다. 하나임푸드 사진 6장은 카카오톡 압축본(1058×1411)이지만 사례 갤러리에는 충분하다.
7. **우일이엔씨 구조**(1차 확인): 회사소개 / 사업분야 4개 하위 페이지 / 시공사례 2종 / 온라인문의(FAQ·A/S·견적) / 고객지원(한전서류 절차·공지). 사례 제목은 "지역 + 건물 + 공사 + 용량" 공식을 쓰고, 상세 내용은 네이버 블로그로 연결된다. 약점으로는 2021년에 멈춘 공지, 똑같은 히어로 슬라이드 3장, 자리표시 썸네일, 중복 사례가 있다. 자체 제작 PHP 사이트이고 제작사는 Threeway(web2002.co.kr)이다.

## 3. 단계별 계획 (각 단계에 통과 조건이 있다)

### Phase 0 — 셋업과 자료 정리
- 계획 사본을 `docs/PLAN.md`로 옮긴다. `.gitignore`에 `_client/`, `research/_raw/`, `node_modules/`, `dist/`를 넣는다.
- 압축 파일 2개를 각각 새 빈 폴더 `_client/김해미술관/`, `_client/하나임푸드/`에 푼다(신뢰하지 않는 데이터로 취급).
- `docs/intake.md`에 위 "현재 자료 진단"을 정리한다. 사진은 직접 열어 보고 용도(히어로 후보 / 사례 갤러리 / 공사 전·후 / 사용 불가)를 표시한다.
- **통과 조건**: 받은 파일이 모두 intake.md에 용도와 함께 기록되어 있다.

### Phase 1 — 우일이엔씨 역공학 (클라이언트 요청)
- **도구**: `aside-browser` 스킬(Aside)로 전 페이지를 탐색하고, 데스크톱·모바일 스크린샷과 인터랙션(GNB 호버, 모바일 메뉴, 히어로 슬라이더, 플로팅 상담 버튼)을 기록한다. REA(`inspect_web_page`, `capture_web_screenshot`, `analyze_web_bundle`)로 DOM, CSS, 스크립트를 추출해 브레이크포인트, 색상, 폰트, 간격을 측정한다.
- **산출물** `research/wooilenc/REPORT.md`:
  1. 전체 사이트맵(IA)
  2. 페이지별 섹션 순서와 간단한 와이어 스케치
  3. 컴포넌트 목록(헤더/GNB, 히어로, 사업 카드, 사례 카드·목록·페이지네이션, 서브 헤더/LNB, 플로팅 상담 바, 푸터)
  4. 추정 디자인 토큰(색, 폰트, 글자 크기, 간격, 브레이크포인트)
  5. 인터랙션과 모션
  6. 콘텐츠 패턴(사례 제목 공식, 한전 서류 절차 페이지, FAQ, A/S 신청)
  7. 유입 구조(네이버 블로그 연동, 메타 태그, 대표번호)
  8. 약점 목록
  9. **가져올 것 / 바꿀 것 / 버릴 것** 표와 볼트온 사이트맵 초안
- 원본 캡처와 추출 코드는 `research/_raw/`(gitignore)에만 둔다. 볼트온 코드에 우일이엔씨 코드를 복사하지 않는다.
- **통과 조건**: 9번 표와 볼트온 사이트맵 초안이 완성되어 있다.

### Phase 2 — grill-with-docs (`grilling` + `domain-modeling` 스킬)
- 나를 대상으로 그릴링을 진행해서 질문을 두 갈래로 나눈다.
  - **(A) 내가 정할 수 있는 것** → `docs/adr/`에 ADR로 확정한다. 예: 0001 스택, 0002 사례 관리 방식, 0003 문의 방식, 0004 레퍼런스 반영 원칙, 0005 도메인 소유 구조, 0006 사이트맵.
  - **(B) 클라이언트만 답할 수 있는 것** → 2차 요청 목록(아래 4절)에 넣는다.
- 루트에 `CONTEXT.md`(용어집)를 만든다. 계약전력, 증설, 승압, 수변전설비(수배전반), 변압기(TR), MOF, 인입선, 내선공사, kVA/kW, 한전 신청, 사용전검사, 준공 같은 용어를 정의한다. 사이트 문구와 클라이언트 소통은 이 용어를 기준으로 한다.
- **통과 조건**: 2차 요청 항목마다 "이것을 모르면 무엇이 막히는가"가 한 줄씩 적혀 있다.

### Phase 3 — 2차 요청 (한 번에, 짧게)
- 카카오톡 메시지 1개로 보내고, 필요하면 1페이지 체크리스트(docx 또는 이미지)를 첨부한다. 5분 통화로 끝나는 항목은 통화로 처리한다.
- 같은 메시지에 **작업 범위 요약**(페이지 목록, 수정 3회, 오픈 후 사례 추가 방식, 비용 선결제 후 청구)을 넣어 확인받는다. 보수가 품질에 따라 정해지는 구조이므로, 범위를 미리 글로 남겨 두어야 나중에 흔들리지 않는다.
- 파일: `docs/client/2차요청.md`
- **통과 조건**: P0 항목이 모두 답변되었다. P1 항목은 답변이 없으면 기본안으로 진행한다.

### Phase 4 — 디자인 시안 (= 요청서의 "첫 화면 확인")
- 로고 JPG를 **SVG로 다시 그린다**(트레이싱 후 정리). 파비콘과 OG 이미지도 만든다. 영문 상호가 확정된 뒤 로고 글자를 맞춘다.
- 디자인 토큰: 로고의 남색을 주색으로, 번개의 연두색은 아주 적게 강조색으로 쓴다. 회색 계열, Pretendard 폰트(OFL), 큰 글씨, 넉넉한 여백을 기본으로 한다. 사진은 적게 쓴다.
- 메인 첫 화면 시안 **2~3개**(데스크톱 + 모바일)를 Cloudflare Pages 미리보기 주소로 전달한다.
  - A: 우일이엔씨 흐름에 충실한 정돈형
  - B: 큰 타이포그래피 중심의 단정형
  - C: 현장 사진과 숫자(용량, 사례 수)를 앞세운 신뢰형
- P1 답변을 기다리는 동안 병행할 수 있다. P0 중 영문 상호만 로고에 영향을 준다.
- **통과 조건**: 장준혁 님이 시안 1개를 고르고 수정 메모를 준다.

### Phase 5 — 전체 제작
- **페이지(초안, Phase 1 결과로 보정)**
  - 홈: 히어로(소개문 + 전화·카톡) → 사업분야 5개 → 진행 절차(한전 서류 포함) → 대표 시공사례 2건(넓은 카드, 공사 전·후) → 한전 신청 안내 배너 → 회사 정보(면허·사업자번호) + 연락처
  - 회사소개: 회사 개요(사업자 정보, 면허), 강점(정직한 견적, 안전 시공, A/S), 위치(네이버 지도 링크)
  - 사업분야: 분야별 하위 페이지(검색 유입에 유리). 문구는 새로 작성한다
  - 시공사례: 목록(분야 필터) + 상세(갤러리, 공사 전·후, 지역·용량·기간). 제목은 "지역 + 건물 + 공사 + 용량" 공식을 따른다
  - 한전 신청 안내(ADR 0004). FAQ는 사업분야 페이지 안에 넣는다(내가 초안 작성 → 확인만 받음)
  - 시공사례 필드: 제목·지역·건물 유형·사업분야·용량·완공 연월·기간·작업 태그·사진(전·중·후). 목록 아래 익명 공사 이력 표
- **공통**: 헤더/GNB, 모바일 메뉴, 모바일 하단 고정 전화·카카오 버튼, 푸터(상호, 대표, 사업자번호, 면허번호, 주소, 연락처)
- **이미지 처리**: 위치정보(EXIF/GPS) 제거, Astro `<Image>`로 webp/avif와 반응형 크기를 만든다.
- **SEO**: 페이지별 title/description, OG 태그, `sitemap.xml`, `robots.txt`, JSON-LD(LocalBusiness/Electrician), 지역 키워드(남양주, 경기, 고압 수변전, 전기 증설)
- **통과 조건**: 모든 페이지가 미리보기 주소에서 동작하고, 아래 검증 항목을 통과한다.

### Phase 6 — 수정 (최대 3회)
- 수정 요청은 한 번에 모아서 받는다(요청서에서 약속한 원칙). 회차별 요청과 반영 내용을 `docs/revisions.md`에 기록한다.

### Phase 7 — 오픈
- 도메인 voltonenc.com은 법인 설립을 기다리지 않고 **장준혁 대표 개인 명의**로 산다(2026-11-14 결정). 법인이 생기면 명의를 법인으로 바꾼다. 결제만 내 카드로 한다.
- Cloudflare DNS 연결, Pages 사용자 도메인 설정, HTTPS를 적용한다.
- 네이버 서치어드바이저와 구글 서치 콘솔에 등록하고 사이트맵을 제출한다.
- 카카오톡 채널 프로필에 홈페이지 주소를 연결한다.
- 네이버 스마트플레이스(지도) 등록은 대표의 네이버 계정이 필요하므로 클라이언트와 함께 진행한다.
- **오픈 전제 조건**: 법인 설립, 사업자등록, 전기공사업 등록이 끝나고 그 정보를 `company.ts`에 채웠다(시공 서비스를 광고하는 사이트이므로 등록 전에 열지 않는다).
- **통과 조건**: 실제 도메인에서 모든 페이지가 열리고, 안드로이드·아이폰 실기기에서 전화·카카오 버튼이 동작한다.

### Phase 8 — 인계와 정산
- 도메인과 Cloudflare 계정을 인계한다. 비밀번호는 문서에 적지 않고 전화로 전달한다(요청서 원칙).
- 운영 안내 1장: 새 사례를 보낼 때의 형식(사진 원본 + 지역, 건물, 공사 종류, 용량, 기간, 공사 전·후 표시).
- 비용 정산서: `docs/costs.md`와 영수증을 합쳐 최종 청구에 포함한다.
- 포트폴리오에 등록한다(6-7에서 허락받음).

## 4. 2차 요청 우선순위

### P0 — 없으면 오픈할 수 없음 (반드시 받기)

1·2·3번은 법인 설립 후에 나온다. 제작을 막지 않고, **오픈 직전에 설정 파일에 채운다.** 4·5·6번은 지금 받는다.

| # | 요청 | 막히는 것 |
|---|---|---|
| 1 | **사업자등록증 사진** | 사업자번호(빈칸), 정식 상호(법인이면 "주식회사" 표기), 개업일(연혁 대체), 도로명 주소. 푸터가 완성되지 않는다 |
| 2 | **전기공사업 등록증 사진** (3-6의 '없음'은 착오인지 확인) | 면허번호 표기. 신뢰도에 가장 큰 요소이다 |
| 3 | **영문 상호 확정**: Volt on E&C인가, BOLT-ON E&C인가 | 도메인 이름과 로고 글자가 정해지지 않는다. 사용 가능한 도메인 후보 2~3개를 미리 조회해서 함께 보낸다 |
| 4 | **카카오톡 채널 주소** (채널이 없으면 개설 안내) | 상담 버튼의 연결 대상이 없다 |
| 5 | **누락된 사례 사진 3곳**(서대문형무소, 제이알 배터리, (주)조양), 카카오톡 '원본'으로 | 사례 5곳 중 3곳이 빈다 |
| 6 | **사례에 실제 현장·회사 이름을 써도 되는지** | 거래처 비공개 답변과 충돌한다. 안 되면 "청주 식품공장 변전실 공사"처럼 익명으로 표기한다 |

### P1 — 품질을 크게 올림 (같은 메시지에 "가능하면"으로)
| # | 요청 | 답이 없으면 |
|---|---|---|
| 7 | 사례별 정보: 지역 / 건물 유형 / 사업분야 / 용량(kVA·kW) / 완공 연월 / 공사 기간 / 공사 전·중·후 사진 구분 (김해 미술관 연도 2025 ↔ 개관 2026-04 함께 확인) | 모르는 항목은 비워 두고 화면에서 숨긴다 |
| 8 | 사업분야를 "고압 수변전설비 / 전기 증설·승압 / 변압기 교체 / 내선·리모델링 / 신·증축"으로 정리했는데 맞는지 (ADR 0006) | 이 정리대로 진행한다 |
| 9 | 대표 경력 연수, 보유 자격증(전기기사 등), 보유 장비 | 신뢰 요소 섹션을 줄인다 |
| 10 | 문의 폼이 필요한지 | 폼 없이 전화 + 카카오톡으로 간다(개인정보처리방침도 불필요) |
| 11 | 비용 구조 합의 (6-3 '만나서 상의' 미결) → 별도 메시지로 보낸다 | — 반드시 오픈 전에 합의한다 |
| 12 | 사진 없는 최근 공사 이력 한 줄씩 (지역 / 공사 종류 / 용량 / 연도). 이후에도 수시로 받는다 | 시공사례만 보여 준다 |

### 요청하지 않음 — 내가 처리
- 로고 벡터 원본 → JPG를 직접 SVG로 다시 그린다.
- 사업분야 문구 → 새로 쓰고 사실 확인만 받는다.
- 연혁 → 사업자등록증의 개업일 한 줄로 대체한다.
- FAQ → 내가 초안을 쓰고 확인만 받는다.
- 분위기 사진 → 라이선스가 확인된 무료 이미지를 쓴다(요청서에서 이미 고지함).
- 도로명 주소 → 직접 조회한다(녹촌리 380-1).
- 하나임푸드 사진 원본 재요청 → 압축본으로 충분하다.
- 사진 위치정보 → 내가 제거한다.
- 네이버 지도 등록 → 오픈 후 함께 진행한다.

## 8. 검증
- **빌드**: `npm run build`와 `npx astro check`가 오류 없이 통과한다.
- **성능·SEO**: Lighthouse 모바일 기준 Performance, Accessibility, SEO, Best Practices가 모두 90 이상이다.
- **반응형**: 360px 폭에서 가로 스크롤이 생기지 않는다. 데스크톱(1440px)과 태블릿(768px)도 확인한다(Aside 또는 Playwright 스크린샷).
- **링크**: 모든 내부 링크와 `tel:`, 카카오 채널 링크가 동작한다(실기기 확인 포함).
- **사진**: 배포된 이미지에 GPS 정보가 남아 있지 않다(EXIF 확인 스크립트).
- **문구**: 사이트 문구에 우일이엔씨 문장과 겹치는 문장이 없다(`research/_raw/`의 텍스트와 대조).
- **정보 정확성**: 푸터의 상호, 대표자, 사업자번호, 면허번호, 주소가 등록증 사진과 일치한다.
- **오픈 후**: 네이버 서치어드바이저와 구글 서치 콘솔에서 사이트맵 수집이 확인된다.
